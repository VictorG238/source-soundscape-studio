# Source 1 audio resources

- A soundscape's `wave` is a physical path below `sound/`, such as `ambient/wind.wav`. SDK 2013 passes `playlooping` and `rndwave` samples to the engine's ambient sound API. Its sound-character helpers define leading modifiers such as `*` for streaming and `#` for dry mix. Editing an existing reference keeps its modifiers. [Soundscapes](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/c_soundscape.cpp) · [Sound characters](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/soundchars.h)
- `gameinfo.txt` declares ordered filesystem mounts. The installed Half-Life 2 configuration puts alphabetically expanded custom mounts and named VPKs before loose game content. Raising The Bar: Redux additionally mounts Mapbase packages and HL2/Episode content. The studio uses the existing resolver order, with explicitly configured sources first. [Filesystem interface](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/filesystem.h) · [Gameinfo.txt](https://developer.valvesoftware.com/wiki/Gameinfo.txt)
- Source 1 VPK v1/v2 indexes can reference preload bytes, embedded data and numbered chunks. The catalog lists names and lengths from the directory index. It reads sample data only when requested. Identical relative paths are grouped by the resolver's priority. A shadowed copy can be auditioned by source, while a soundscape reference addresses the effective copy. [VPK format](https://developer.valvesoftware.com/wiki/VPK_(file_format))
- `scripts/game_sounds_manifest.txt` registers soundscript files containing logical events with parameters and one or more waves. `scripts/soundscapes_manifest.txt` registers soundscape scripts. The browser lists physical audio and uses physical paths for edits. [Soundscripts](https://developer.valvesoftware.com/wiki/Soundscripts) · [Sound emitter](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/shared/SoundEmitterSystem.cpp)
- Source WAV loops commonly use RIFF cue points. The browser also reads forward `smpl` loops for auditioning and identifies them separately. Container, encoding and loop support depend on the target branch. WAV and MP3 are common Source formats, while editor support for Ogg Vorbis and FLAC comes from Symphonia. [Looping audio](https://developer.valvesoftware.com/wiki/Looping_a_Sound)

## Portable soundscapes

- Use `playlooping` with one `wave` and a WAV with a cue point. Use `playrandom` with short, non-looping WAVs and a `time` in seconds. Put every random variant in `rndwave`, including a single variant. The SDK schedules its first random event at half the sampled interval. The wiki warns that looped random clips can continue after the next soundscape activates. [Soundscape rules](https://developer.valvesoftware.com/wiki/Soundscape#Rules) · [Source SDK 2013](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/c_soundscape.cpp)
- Use volume between 0 and 1, pitch near 100 percent, and an ordered `min,max` pair for random intervals. Scalar volume and pitch are the conservative choice for looped layers. The wiki describes looped parameters as scalar, while SDK 2013 samples ranges for both volume and pitch when it processes the loop. Studio accepts existing ranges. [Common keyvalues](https://developer.valvesoftware.com/wiki/Soundscape#Common_keyvalues) · [Source SDK 2013](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/c_soundscape.cpp)
- Give soundscapes globally unique names. SDK 2013 loads global scripts via `scripts/soundscapes_manifest.txt` and map-local scripts via `scripts/soundscapes_<mapname>.txt`. The wiki documents `maps/<mapname>_soundscapes.txt` for Mapbase. Verify placement and playback in the target game using a VIS-compiled map and `soundscape_debug`. In older branches, use a numbered emitter for positional loops. The preview does not simulate map emitters or DSP. [Custom soundscapes](https://developer.valvesoftware.com/wiki/Soundscape#Storing_and_using_custom_soundscapes)
